# Hawk Manual

Hawk is an R7RS Scheme implementation with a bytecode compiler, VM, garbage
collector, tracing JIT, and native emitters for x86-64 and aarch64. This manual
documents Hawk-specific behavior. It does not repeat the R7RS language or
standard library reference.

The public Hawk-specific Scheme library is `(hawk)`. The low-level `(hawk sys)`
library is an implementation interface and is intentionally not documented here
as a user API.

## Running Hawk

Run a Scheme script:

```sh
hawk program.scm
```

The first non-option argument is the script path. Remaining arguments are
available to the program through `(scheme process-context)` `command-line`.
Use `--` to stop option parsing when a script argument starts with `-`.

```sh
hawk program.scm -- --not-a-hawk-option
```

Useful command-line options:

- `-o`, `--joff`: disable the JIT and run with the bytecode VM only.
- `-i PATH`, `--image PATH`: load an explicit `.bc` image instead of the
  embedded or default boot image.
- `-D NAME`: add `NAME` to the Scheme feature list before loading the script.
- `-I DIRECTORY`: prepend a directory to the Scheme library search path.
- `-A DIRECTORY`: append a directory to the Scheme library search path.
- `--list`: compile the script and print bytecode without running it.
- `--exe`: build an executable from a `.scm` source file.
- `-p`, `--profile`: print VM, GC, and JIT timing information at exit.
- `--version`: print the version string and exit.
- `-h`, `--help`: print command-line help and exit.

Debugging options:

- `-v`, `--verbose[=CATEGORIES]`: enable verbose logging. Without categories,
  all logging is enabled. Categories are comma-separated: `gc`, `trace`,
  `record`, `jit`, `regalloc`, `asm`, `ir`.
- `--unsafe`: disable array bounds checks.
- `-m NUMBER`, `--max-trace NUMBER`: stop JIT compilation after `NUMBER`
  traces and continue interpreting.
- `-d`, `--dump`: emit Linux perf JIT dump information.
- `-s SEED`: set the random tracing schedule seed when Hawk was built with
  `USE_RANDOM_SCHEDULE`.

`--exe` writes `FILE.hawk-image.c` and `FILE.hawk-image.bc` next to
`FILE.scm`, then links `FILE` against `libhawk_core` using the system linker.
Install Hawk first, or set normal compiler and loader paths such as
`LIBRARY_PATH` and `LD_LIBRARY_PATH`, so `-lhawk_core` can be found.

## The `(hawk)` Library

Import Hawk-specific bindings with:

```scheme
(import (scheme base) (hawk))
```

`(add-feature feature)`

Adds `feature` to the current feature list used by `cond-expand` and library
loading. `feature` should be a symbol.

`(library-paths)`

Returns the current Scheme library search path list.

`(library-paths-set! paths)`

Replaces the Scheme library search path list with `paths`. Each entry should be
a string directory path. Command-line `-I` paths are prepended before default
paths, and `-A` paths are appended after default paths during startup.

`(compile form environment dump?)`

Compiles `form` and returns a closure. If `environment` is false, Hawk expands
`form` as a program; otherwise it expands in the given environment. If `dump?`
is true, Hawk prints the generated bytecode.

```scheme
(define thunk (compile '(begin (+ 1 2)) #f #f))
(thunk)
```

`(flush-trace-cache)`

Clears currently recorded JIT traces and resets tracing state. This is mainly
useful for debugging, benchmarking, and interactive evaluation workflows.

`(jit)`

Returns the current JIT state as either `enabled` or `disabled`.

`(jit enabled?)`

Enables or disables the JIT. Disabling the JIT also clears recorded traces.
Returns the resulting state, `enabled` or `disabled`.

```scheme
(jit #f)  ; => disabled
(jit #t)  ; => enabled
```

`(save-image-and-die restart path compress-level)`

Writes a heap image and exits the process. `restart` is the closure to run when
the image is loaded, `path` is the output path, and `compress-level` controls
image compression when compressed image support is available. This procedure
does not return.

## Runtime Environment

These environment variables tune the runtime:

- `GC_SPACE`: heap space size in MB. Default: `2048`.
- `GC_COLLECT`: allocation interval before collection in MB. Default: `32`.
- `GC_SATB`: set to `0` to disable SATB cycle tracing.
- `GC_SATB_WASTE`: enable SATB tracing and set the SATB waste threshold.
- `JIT_CACHE_SZ`: JIT code cache size in MB. Default: `4`.

Example:

```sh
GC_SPACE=4096 JIT_CACHE_SZ=16 hawk program.scm
```

The `gc` verbose category prints GC configuration and collection diagnostics:

```sh
hawk -v=gc program.scm
```

## Images

Hawk starts from a Scheme image. Release builds normally embed the boot image in
the `hawk` executable. Development builds can also load an image from disk.

Use `--image` to load a specific image:

```sh
hawk --image boot/img.scm.bc program.scm
```

When zstd support is available, Hawk can use compressed `.bc.zstd` images. If a
build has no embedded image, Hawk looks for `boot/img.scm.bc.zstd` when zstd is
enabled and `boot/img.scm.bc` otherwise.

## FFI

Hawk currently has a low-level foreign call mechanism used by the runtime and
libraries. It is not exposed as a stable public `(hawk)` binding. This section
documents how it works today for maintainers and for code that intentionally
uses the implementation interface.

A foreign call is described by a literal signature:

```scheme
'(return-type "symbol_name" (arg-type ...))
```

Supported types:

- `uint8`
- `int32`
- `int64`
- `uint64`
- `double`
- `string`
- `gc_obj`
- `bool`

At runtime, Hawk resolves `"symbol_name"` with `dlsym` from the current process
image. This means the target symbol must already be linked into the executable,
loaded shared libraries, or `libhawk_core` with default symbol visibility.

Argument conversion:

- Integer types require Scheme fixnums.
- `double` accepts fixnums or flonums and passes a C `double`.
- `string` requires a Scheme string and passes its raw `char *` buffer.
- `gc_obj` passes the raw Hawk object representation.
- `bool` passes `1` for `#t` and `0` for any other Scheme value.

Return conversion:

- Integer returns become fixnums.
- `double` returns become flonums.
- `bool` returns become `#t` or `#f`.
- `gc_obj` returns are treated as raw Hawk object values.
- `string` returns must be a heap-allocated C string owned by the caller;
  Hawk copies it into a Scheme string and frees the original with `free`.

The VM path parses the signature, resolves the symbol, converts arguments, and
calls a small architecture-specific assembly stub. The JIT can record some
foreign calls directly, but only when the signature and argument types fit the
native calling convention. Calls with too many GPR/FPR arguments, unsupported
argument types, or mismatched runtime values abort tracing and continue in the
VM.

Important caveats:

- The raw `char *` for a Scheme string is not GC-stable if the foreign callee
  can reenter Scheme or otherwise trigger collection.
- `gc_obj` is a runtime-internal representation; C code using it must obey the
  GC and object representation rules.
- This interface should be treated as unstable until Hawk grows a documented
  public FFI library.

## Build-Time Features That Affect Runtime Behavior

Most build instructions live in `README.md`. The following build choices affect
behavior described in this manual:

- `BOOTSTRAP=ON` builds the Scheme boot image from source during the build.
- `ZSTD=ON` enables compressed heap image support when libzstd is found.
- `DISASSEMBLE=ON` enables capstone-backed disassembly for verbose assembly
  output when capstone is found.
- `USE_RANDOM_SCHEDULE=ON` enables the `-s SEED` random schedule debugging
  option.

Hawk currently has native emitters for x86-64 and aarch64.
